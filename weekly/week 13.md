## Topic 1. LangChain 기반 RAG 시스템의 주요 구성 요소

### 1. 핵심 개념 요약
RAG는 LLM의 할루시네이션, 블랙박스, 지식컷오프의 한계를 보완하고자 탄생하였다.
외부 데이터를 통한 검색으로 보강한 생성을 하며, 검색기/증강/생성기의 3구조를 가지고 있다.

### 2. 상세 내용

#### RAG란?
- 질문과 관련된 문서를 먼저 찾아서 질문과 함께 건네준 뒤, 내용을 근거로 답변을 생성

**[세가지 구조]**
- 검색기(retriever): 질문과 관련 있는 부분을 찾아오는 역할
- 증강(augmentation): 찾은 문서와 사용자의 질문을 묶어 생성기에게 건넬 프롬프트 생성
- 생성기(generator): 문서를 바탕으로 질문에 맞는 답변을 생성

#### 구성 요소별 역할
**1단계: 인덱싱(데이터 준비 및 저장)**
- Document Loader: 외부 데이터(PDF, TXT, CSV..)를 LangChain이 읽을 수 있는 문서 객체로 다운로드
- Text Splitter: 긴 문서를 LLM이 처리하기 좋은 청크(chunk)단위로 분리 + 문맥 유지를 위한 overlap
- Embedding Model: 청크를 의미 기반의 숫자 벡터 배열로 변환
- Vector Store: 벡터와 텍스트 청크를 저장 + 질문 벡터와 유사한 데이터 서치

**2단계: 검색 및 생성**
- Retriever: 질문과 의미가 가장 유사한 청크 검색
- LLM: 검색된 context와 질문을 조합하여 프롬프트 생성 + LLM이 최종 답변 생성

## Topic 2. RAG 시스템 성능 평가 방법 (독립 평가 vs 종단간 평가)

### 1. 핵심 개념 요약
RAG의 성능을 평가하는 방법에는 어떻게 평가하냐에 따라 독립 평가와 종단간 평가로 나뉜다.
독립 평가는 검색기와 생성기를 따로 평가하며, 종단간 평가는 가장 마지막 도출된 답변을 통해 성능을 평가한다.

### 2. 상세 내용
**[평가의 중요성]**
- RAG의 시스템 평가는 검색과 생성의 단계에서 진행됨
- 정성적 평가만으로는 오류 개선이 어렵움
- 정량적 평가를 통해 병목이 발생하는 단계를 파악 &rarr; 개선 

#### 평가 방법의 종류
1) 검색 평가 방법

| 평가 항목 | 설명 |
|------|------|
| Recall@K | 상위 K개 결과에 관련 문서가 포함된 비율 |
| Precision@K | 상위 K개 결과 중 관련 문서의 비율 |
| MRR | 첫 관련 문서의 순위 역수의 평균 |

2) 생성 평가 방법

| 평가 항목 | 설명 |
|------|------|
| Faithfulness(충실성) | 답변이 컨텍스트에 충실한 정도 (할루시네이션 여부) |
| Answer Relevancy(답변 관련성) | 답변이 질문에 적절히 대답하는 정도 |
| Context Precision | 검색된 컨텍스트 중 실제 답변에 사용된 비율 |
| Context Recall | 정답을 생성하는 데 필요한 정보가 컨텍스트에 포함된 비율 |

#### 독립 평가(Component-level) vs 종단간 평가(End-to-end)
**독립적 평가**
- 정의: 검색기와 생성기를 따로 평가함
- 장점: 어느 부분에서 병목 현상이 발생했는지 약점을 파악하기 용이
- 단점: 실사용 감각 파악 어려움

**종단간 평가**
- 정의: 최종 답변만 보고 평가
- 장점: 실사용에서의 품질 평가 가능, 시스템의 전체 수준 확인
- 단점: 병목 위치 파악 어려움

## Topic 3. RAG에서의 Agent 개념과 구현 방식

### 1. 핵심 개념 요약
검색과 생성의 흐름을 개발자가 고정하지 않고, **LLM이 스스로 판단·계획·반복**하도록 제어권을 넘긴 RAG 구조이다.

### 2. 상세 내용

#### Agentic RAG란?
- Agent: 스스로 생각하고 계획을 세우며, 도구를 사용하여 목표를 달성하는 자율적인 프로그램  
- 기본적인 RAG 기술(외부 데이터 &rarr; 검색 &rarr; 생성) + AI Agent의 실행 루프 결합

| 특징 | 기존 RAG | Agentic RAG |
|-----|-------------|---------|
| 유연성 | 단일 외부 데이터 | 여러 외부 지식 기반 데이터 + 도구 |
| 적응성 | 정적 규칙 기반 질의 | 적응형 지능형 문제 해결 방식(멀티에이전트 시스템) |
| 정확성 | 결과 최적화 및 검증 X | 생성 및 판단 반복을 통한 최적화 |
| 확장성 | X | O |
| 멀티모달 | X | O |

- **단점**:
    - 에이전트 작동 증가 &rarr; 비용 증가
    - LLM의 아웃풋 생성 지연 시간 증가

#### 구현 방식
| 방식 | 설명 |
|------|------|
| Retriever를 Tool로 등록 | 검색기를 도구로 감싸 LLM이 호출 여부와 쿼리를 직접 결정 |
| LangChain AgentExecutor | ReAct 루프(생각→도구 호출→관찰)를 자동으로 반복 실행 |
| LangGraph | 검색·평가·재검색을 노드로 두고 조건부 분기와 순환을 설계 |
